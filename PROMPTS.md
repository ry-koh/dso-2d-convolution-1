# Regeneration Guide

How to reproduce every file in this repository from scratch. Covers both the
generated artefacts (testbench, vectors, visualiser) and the decisions baked into
the RTL that would need to be re-stated to regenerate the source files.

---

## What Is Generated vs Hand-Written

| File(s) | Origin |
|---|---|
| `src/conv2d.vhd`, `src/line_buf.vhd`, `src/win_buf.vhd` | AI-generated RTL (Claude), based on the design decisions in the RTL Design Decisions section below |
| `tb/conv2d_tb.vhd` | Generated by `scripts/gen_tb.py` |
| `tb/vectors/c001..c324_{input,expected}.txt` | Generated by `scripts/gen_tb.py` |
| `tb/visualize.html` | Generated by `scripts/gen_tb.py --html` |
| `scripts/gen_tb.py` | AI-generated Python script (Claude) |

Never hand-edit `tb/conv2d_tb.vhd` — it will be overwritten on the next run.

## Regenerating the Testbench and Vectors

From the repo root:

```
python scripts/gen_tb.py
```

This writes:
- 648 vector files (`tb/vectors/c001..c324_input.txt` and `c001..c324_expected.txt`)
- `tb/conv2d_tb.vhd` (324 base DUT instances + 3 back-pressure + 30 stress scenarios)

To also regenerate the interactive HTML visualiser:

```
python scripts/gen_tb.py --html
```

This additionally writes `tb/visualize.html`.

**Requirements:** Python 3, standard library only (no third-party packages).

## Configuration Matrix

`gen_tb.py` generates one DUT instance per combination of:

| Axis | Values |
|---|---|
| Kernel size | 3×3, 3×5, 3×7, 5×3, 5×5, 5×7, 7×3, 7×5, 7×7 |
| EDGE_MODE | ZERO, REPLICATE, TOROIDAL |
| FLUSH | false, true |
| Frame size (LINE_WIDTH × FRAME_HEIGHT) | 8×8, 16×4, 4×16, 3×3, 5×5, 8×1 |

Total: 9 × 3 × 2 × 6 = **324 configurations**.

DATA_WIDTH is fixed at 8 for the testbench. The RTL generic accepts any positive integer.

## Stress Scenarios (30)

Defined in `STRESS_CONFIGS` inside `gen_tb.py` as:

```
(kr, kc, mode, flush, lw, fh, sv_h, sv_l, mr_h, mr_l, description)
```

`sv_h`/`sv_l` = `s_tvalid` HIGH/LOW cycle counts. `mr_h`/`mr_l` = `m_tready` HIGH/LOW
cycle counts. `(0, 0)` means always HIGH (no throttling on that signal).

Three groups:
1. `s_tvalid` pattern only — `m_tready` always HIGH
2. `m_tready` pattern only — `s_tvalid` always HIGH
3. Both signals varied simultaneously

Each stress DUT uses the same RTL generics and golden vectors as its base config.
The checker fires on `mvalid AND mready` — the AXI4-Stream handshake — so spurious
extra outputs and missing outputs both produce mismatches.

## Running in Vivado

1. Create a Vivado project targeting **XC7Z020-CLG484-1**.
2. Add `src/line_buf.vhd`, `src/win_buf.vhd`, `src/conv2d.vhd` as design sources.
3. Add `tb/conv2d_tb.vhd` as a simulation source.
4. Set all four `.vhd` files to **VHDL 2008** (right-click → Properties → File type).
   The testbench uses VHDL-2008 constructs; Vivado defaults to VHDL 1993.
5. Copy `tb/vectors/` into the xsim working directory:
   `<project>.sim/sim_1/behav/xsim/vectors/`
   — or adjust the path constants at the top of `conv2d_tb.vhd`.
6. Set `conv2d_tb` as the simulation top.
7. Run Behavioral Simulation. Recommended run time: **40 000 ns**.
   Each config prints `PASS` or `FAIL` to the Tcl console on completion.

## RTL Design Decisions (needed to re-generate `src/` from scratch)

These are the decisions that would need to be re-stated to an AI or a new engineer
to reproduce the RTL files. They are locked — do not change without re-running
synthesis to verify the impact.

### Target and toolchain
- Device: Avnet ZedBoard, Zynq-7000 **XC7Z020-CLG484-1**
- Toolchain: Vivado xsim, VHDL-2008, IEEE standard packages only
- Scope: simulation only — no bitstream, no board bring-up

### I/O contract
- Input: one AXI4-Stream port (`TDATA`, `TVALID`, `TREADY`, `TLAST`, `TUSER[0]` SOF)
- Output: `KERN_ROWS × KERN_COLS` AXI4-Stream ports, one per tap, same signal set
- `m_tready` is a vector — one bit per tap — AND-gated internally into `all_ready`
- No coefficient multiplication; raw tap pixel values only

### Clock and reset
- Single clock domain
- Synchronous active-high reset

### Storage split
- Row history (KERN_ROWS−1 rows × LINE_WIDTH pixels): BRAM (`line_buf`)
  — attribute `ram_style = "block"` forces BRAM inference; no reset on the array
- Column window (KERN_ROWS × KERN_COLS pixels): FF shift register (`win_buf`)

### Pipeline depth
- 2 clock cycles from trigger pixel accepted to `m_tvalid` asserted
- Stage 1: BRAM synchronous read settles
- Stage 2: `p_out_reg` captures full window and asserts `m_tvalid`

### Edge modes
- `ZERO`: `new_row` signal clears column shift register at each row start;
  `row_valid` vector zeroes BRAM slots not yet written within the current frame
- `REPLICATE`: combinational `p_edge_out` stage clamps OOB coordinates to nearest
  valid tap using delayed pixel coordinates (`m_col_r`, `m_row_r`)
- `TOROIDAL`: stream-linear model via `tor_buf` shift register, depth
  `2 × TOR_MAX_POS + 1`; bypasses `line_buf`/`win_buf` entirely

### FLUSH
- `FLUSH=true`: after TLAST, inject `HALF_R = (KERN_ROWS−1)/2` dummy zero-rows;
  stall real input (`s_tready` deasserted) during flush; SOF re-arms counters
- `FLUSH=false`: no dummy rows; bottom HALF_R rows of each frame produce output
  using BRAM content from the previous frame

### Synthesis reference (3×3, 8-bit, XC7Z020, project-mode)

| Block | LUTs | Registers | BRAM Tiles |
|---|---|---|---|
| conv2d (total) | 208 | 390 | 1 |
| u_line_buf | 51 | 0 | 1 |
| u_win_buf | 8 | 72 | 0 |
| conv2d logic | 149 | 318 | 0 |

Timing: WNS=inf, TNS=0.000 ns, 0 failing endpoints / 1308 (no user constraints).
