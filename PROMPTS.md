## Regenerating the Testbench, Vectors, and Visualiser

From the repo root:

```
python scripts/gen_tb.py
```

Produces:
- `tb/vectors/c001..c324_input.txt` and `c001..c324_expected.txt` (648 files)
- `tb/conv2d_tb.vhd` (324 base DUT instances + 3 back-pressure + 30 stress scenarios)

To also regenerate the HTML visualiser:

```
python scripts/gen_tb.py --html
```

Adds `tb/visualize.html`.

**Requirements:** Python 3, standard library only.

### Stress scenarios (30)

Defined in `STRESS_CONFIGS` in `gen_tb.py` as `(kr, kc, mode, flush, lw, fh, sv_h, sv_l, mr_h, mr_l, desc)`.
`sv_h/sv_l` = `s_tvalid` HIGH/LOW cycle counts; `mr_h/mr_l` = `m_tready` HIGH/LOW cycle counts;
`(0, 0)` = always HIGH. Three groups: `s_tvalid` only, `m_tready` only, both varied.

## Running in Vivado

1. Create a Vivado project targeting **XC7Z020-CLG484-1**.
2. Add `src/line_buf.vhd`, `src/win_buf.vhd`, `src/conv2d.vhd` as design sources.
3. Add `tb/conv2d_tb.vhd` as a simulation source.
4. Set all four `.vhd` files to **VHDL 2008** (right-click → Properties → File type).
   Vivado defaults to VHDL 1993 and will fail to compile otherwise.
5. Copy `tb/vectors/` into the xsim working directory:
   `<project>.sim/sim_1/behav/xsim/vectors/`
6. Set `conv2d_tb` as the simulation top.
7. Run Behavioral Simulation. Recommended run time: **40 000 ns**.

## How the RTL Was Built (decision log from actual session)

This section records the decisions made during the AI session that produced the RTL.
Read it if you need to regenerate or significantly modify `src/`.

### Phase 0 — Project setup and initial prompt

The opening prompt established the full spec before any code was written. Key elements:

- **Toolchain locked:** Vivado xsim, VHDL-2008, IEEE standard packages only.
  No shell scripts, no Makefile flows, no mixed-language modules.
- **Scope locked:** simulation only. No bitstream, no board bring-up, no PS/FCLK.
- **I/O contract locked:** one AXI4-Stream input, M×N AXI4-Stream outputs (one per tap),
  raw pixel values only — no coefficient multiplication.
- **Known failure mode seeded:** a previous design had accidentally inferred LUT-based
  storage instead of BRAM for row buffers. Phase 1 was required to produce a written
  LUT-vs-BRAM comparison with synthesis numbers before any RTL was written.
- **Phase gating:** each phase required a concrete simulation result or written deliverable
  before advancing. No skipping phases.
- **Optimization criteria rule:** whenever more than one implementation approach existed,
  the criteria being optimised (area, latency, readability, timing) had to be stated
  explicitly before choosing.

Setup interview answers (multiple choice):
- AXI4-Stream signal set: TDATA, TVALID, TREADY, TLAST, TUSER[0] (Xilinx video profile)
- Reset style: synchronous, active-high
- DATA_WIDTH: any positive integer (not just 8/16/24)
- Phase 4 generics: EDGE_MODE (ZERO/REPLICATE/TOROIDAL) and FLUSH (on/off)
- No hard maximum on window size — practical limit is device resources

### Phase 1 — Research and architecture

Claude surveyed 3+ open-source HDL convolution implementations and produced:
- A LUT-vs-BRAM storage comparison with synthesis numbers confirming BRAM is the
  correct choice for row buffers (using `ram_style="block"` attribute)
- An architecture proposal: 3-subblock split — `conv2d` (top-level), `line_buf` (BRAM),
  `win_buf` (FF shift register)

Approved with a single word: `approved`.

The Vivado workflow was established at this point: owner creates a project manually,
pastes generated file content into Vivado's editor. No shell scripts.

### Phase 2 — Base RTL (3×3, 8-bit, ZERO, FLUSH=off)

RTL written, pasted into Vivado, and elaborated. First simulation run produced
mismatches. Simulation log pasted back verbatim; Claude diagnosed each bug.

Three bugs found and fixed during Phase 2/3 (see CLAUDE.md Bug Log for full details):
- Bug 1: BRAM row ordering — wrong age ordering on odd-numbered input rows
- Bug 2: Delta-cycle timing — `p_out_reg` captured pre-shift window
- Bug 3: Win_buf column boundary — stale data at start of each new row

Coefficient multiplication was proposed at one point and rejected:
`why are we adding coefficient multiplication`

### Phase 3 — Self-checking testbench

Python golden vector generator and VHDL textio checker written. Back-pressure
(m_tready deassertion) tested and confirmed working.

Reference code from supervisor (`Gemini_AI_code_gen.zip`) was uploaded for analysis.
One idea borrowed (coordinate metasystem for edge modes); the rest rejected due to
known bugs and LUT-based storage.

### Phase 4 — Generalisation (EDGE_MODE, FLUSH, full config matrix)

Toroidal definition required explicit alignment before implementation:

The definition was debated. The chosen model is **stream-linear causal**:
- Tap (tr, tc) = `global_stream[center_g + (tr−HALF_R)×LINE_WIDTH + (tc−HALF_C)]`
- Negative global indices → 0 (warmup zeros before frame 0 pixel 0)
- Implemented via `tor_buf` shift register, bypassing `line_buf`/`win_buf` entirely

FLUSH semantics confirmed in plain language before implementation:
> "each valid output window is outputted per real input pixel, but at the end of a frame,
> if flush is turned on, we will input dummy input pixels so as to make sure this frame
> is completed first before we proceed to the next frame" → confirmed correct

A reference HTML visualiser (`sim_trace.zip`) was uploaded as a specification document
for the toroidal behaviour, which was more precise than describing it in words.

REPLICATE option A (coordinate-based output mux) chosen over option B
(iterative pipeline fill) for area efficiency with large kernels.

Two additional bugs fixed during Phase 4 (see CLAUDE.md Bug Log for details):
- Bug 5: REPLICATE coordinate wrong at SOF after FLUSH
- Bug 6: TOROIDAL xsim BRAM uninitialised propagation

Final 324-config testbench run result: all PASS.

### Stress scenarios — backpressure and timing variation

Requested by supervisor: test with non-continuous input/output handshaking. Patterns
such as `2H/3L` (2 cycles HIGH, 3 cycles LOW) on `s_tvalid` and `m_tready` independently
and simultaneously. 30 stress scenarios added to the testbench and visualiser.

First run produced mismatches in SS004, SS005, SS006, SS010. Fixed. Second run: all PASS.

## Locked Decisions (do not change without re-running synthesis)

| Decision | Value |
|---|---|
| Target device | XC7Z020-CLG484-1 |
| Language | VHDL-2008 |
| Reset | Synchronous, active-high |
| Row buffer storage | BRAM (`ram_style="block"`, no reset on array) |
| Column window storage | FF shift register |
| Pipeline depth | 2 clock cycles (trigger pixel accepted → m_tvalid asserted) |
| m_tready width | Vector (one bit per tap), AND-gated internally |
| Edge mode implementation | Combinational output-stage remapping (`p_edge_out`) |
| TOROIDAL model | Stream-linear causal via `tor_buf` shift register |
| FLUSH | Inject HALF_R dummy zero-rows after TLAST; stall s_tready during flush |
| MAC stage | Out of scope — raw tap pixel values only |
